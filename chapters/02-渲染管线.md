# 02 · 渲染：从一行 drawRect 到一个三角形上屏

本章对着 `core/src/vulkan_renderer.cpp`（1082 行）完整走读：从 App 里 `paint.drawRect(...)` 调用，到屏幕上出现一个三角形，中间每一站都有源码出处。Renderer 只做**帧编排**（acquire → 录制 → 提交 → present），GPU 设施全部下放给 `gpu/` 五个模块。

## 2.0 一个三角形的一生（全景时间线）

1. **App 侧 · Canvas::drawRect** — painter lambda 里画一个矩形 → CPU 三角化成 6 个 UiVertex（32B/个）→ append(clip, textureId=0, v, 6) 进批次
2. **UI 线程 · buildFrame** — 遍历 View 树收集本帧全部顶点 → Canvas（纯 CPU，无 Vulkan 依赖）
3. **帧交接 · FramePipeline** — Canvas + 纹理脏区打包成 Frame，投入双槽队列（见多线程章）
4. **Raster 线程 · Renderer::render** — ① 等 fence → ② acquire 交换链图像 → ③ 顶点 memcpy 进 HOST_VISIBLE 缓冲 → ④ 录制命令 → ⑤ 提交 → ⑥ present
5. **顶点着色器** — `gl_Position = mvp * vec4(pos, 0, 1)`：屏幕像素 → Clip Space（正交投影，w=1）
6. **GPU 固定功能** — 透视除法（空操作）→ 视口变换 → 光栅化成像素 → 片元着色器输出 顶点色 × 纹理（白纹理=1）

> **ℹ️ 为什么可以直接用屏幕像素当顶点坐标**：正交投影（压缩，x/W·2-1）与视口变换（拉伸，(NDC+1)/2·W）数学上精确抵消，framebuffer_x = x。所以 Canvas 里全是屏幕像素，坐标变换只有顶点着色器里一次矩阵乘法。

## 2.1 初始化：四段搭建，注释里写死了依赖顺序

**Renderer::initialize()（vulkan_renderer.cpp:48-73）**

```cpp
bool Renderer::initialize() {
    // ① 地基：instance / surface / 物理与逻辑设备（gpu::VulkanContext）。
    if (!context_.initialize()) return false;
    // ② 纹理设施：descriptor 布局是管线布局的输入（shader 的 set=0），必须先于管线。
    if (!textureCache_.initialize()) return false;
    // ③ 交换链及其下游：imageView / MSAA 颜色图 / renderPass 全部依赖
    //   swapchain 的格式与尺寸，窗口尺寸变化时这一段连同管线整体重建。
    if (!swapchain_.create()) return false;
    if (!uiPipeline_.create(swapchain_.renderPass(), swapchain_.extent(),
                            swapchain_.msaaSamples(),
                            textureCache_.descriptorSetLayout())) return false;
    if (!swapchain_.createFramebuffers()) return false;
    // 离屏效果设施失败仅降级（模糊标记批被忽略，内容照画），不阻断启动。
    if (!createOffscreenEffects()) { EVK_LOGW(...); }
    // ④ 执行设施：命令池、顶点缓冲、命令缓冲、同步原语，与 swapchain 尺寸无关。
    if (!createCommandPool()) return false;
    if (!createVertexBuffers()) return false;
    if (!createCommandBuffers()) return false;
    if (!createSyncObjects()) return false;
    swapchain_.takeRebuildRequest(); // 初始尺寸已用于建链，不必在首帧重复重建。
    return true;
}
```

第 ② 步先于 ③ 是**硬约束**：shader 里 `set=0, binding=0` 的纹理长什么样，必须在管线创建时写进 pipeline layout。shutdown() 严格按相反顺序释放，并且先 `vkDeviceWaitIdle`——销毁仍在被 GPU 使用的对象是未定义行为。

## 2.2 顶点缓冲：每帧 map 一次，够用就翻倍

每个 in-flight 帧槽独占一块缓冲（kMaxFramesInFlight = 2），避免 CPU 覆盖在途顶点。缓冲是 HOST_VISIBLE | HOST_COHERENT 的——CPU 直接 map/memcpy/unmap，写完 GPU 立即可见，**省掉 staging buffer**（每帧只上传少量顶点时最省事）：

**uploadVertices（vulkan_renderer.cpp:264-299）**

```cpp
bool Renderer::uploadVertices(const ui::UiVertex* data, uint32_t count,
                              uint32_t frameSlot) {
    FramePhaseScope phase(FramePhase::VertexUpload);   // 分段计时
    if (count == 0) return true;
    if (!data || frameSlot >= vertexBuffers_.size()) return false;
    if (count > vertexBufferCapacities_[frameSlot]) {
        uint32_t capacity = std::max(kInitialVertexCapacity,   // 8192 顶点起
                                     vertexBufferCapacities_[frameSlot]);
        while (capacity < count) capacity *= 2;              // 不足翻倍扩容
        if (!createVertexBuffer(frameSlot, capacity)) return false;
    }
    void* mapped = nullptr;
    vkMapMemory(context_.device(), vertexBufferMemorys_[frameSlot],
                0, byteSize, 0, &mapped);
    std::memcpy(mapped, data, byteSize);
    vkUnmapMemory(context_.device(), vertexBufferMemorys_[frameSlot]);
    return true;
}
```

扩容路径先建新的、绑好内存、再销毁旧的（createVertexBuffer 尾部），任何一步失败都有对应的回滚（free memory / destroy buffer）。

## 2.3 同步原语：一个初始化细节救过所有人

**createSyncObjects（vulkan_renderer.cpp:321-351）**

```cpp
// semaphore 做 GPU 内部阶段间等待（acquire → 渲染 → 呈现），
// fence 做 CPU 等 GPU；每帧各一套，互不打架。
VkFenceCreateInfo fenceInfo{};
fenceInfo.flags = VK_FENCE_CREATE_SIGNALED_BIT;   // ← 关键

// fence 建成 SIGNALED 初始态：第一帧 render() 的 vkWaitForFences 能立即通过，
// 否则会永久等在一个从没人 signal 过的 fence 上。
```

双缓冲（kMaxFramesInFlight=2）让 CPU/GPU 有一点重叠但不无限堆积。命令池带 `RESET_COMMAND_BUFFER_BIT`，每帧单独 reset 重录某条缓冲。

## 2.4 render() 主循环：七步一帧，注释是按需渲染的设计宣言

**render() 骨架（vulkan_renderer.cpp:416-584）**

```cpp
RenderResult Renderer::render(const ui::Canvas& canvas, ...) {
    constexpr uint32_t kMaxFrameAttempts = 3;   // 本帧内重建重试上限
    for (uint32_t attempt = 0; attempt < kMaxFrameAttempts; ++attempt) {
        if (swapchain_.takeRebuildRequest())     // 尺寸变化先重建再画
            if (!recreateSwapchain()) return RenderResult::Failed;
        if (!swapchain_.matchesRequestedExtent()) {  // 尺寸自愈（折叠屏场景）
            swapchain_.requestRebuild(); continue;
        }
        // ① 等本帧槽位的 fence：把 CPU 领先 GPU 的帧数限制在 2 帧以内。
        //    超时（16ms）把绘制请求留到下一次 VSync，Raster 能返回队列响应 stop。
        fenceResult = vkWaitForFences(device, 1, &inFlightFences_[currentFrame_],
                                      VK_TRUE, 16000000 /*ns*/);
        if (fenceResult == VK_TIMEOUT) return RenderResult::Retry;

        // ② acquire：向交换链申请下一张可写图像
        result = vkAcquireNextImageKHR(device, swapchain_.handle(), waitNanos,
                    imageAvailableSemaphores_[currentFrame_], VK_NULL_HANDLE, &imageIndex);
        if (result == VK_ERROR_OUT_OF_DATE_KHR) {   // 交换链已失效
            if (!recreateSwapchain()) return RenderResult::Failed;
            continue;                                // 用同一 canvas 重画
        }
        // ③ 上传顶点（空 canvas 跳过，录成清屏帧）
        if (!canvas.vertices().empty())
            if (!uploadVertices(canvas.vertices().data(), ..., currentFrame_))
                return RenderResult::Failed;

        // ④ reset fence 必须在确认本帧一定会提交之后做：
        //   若提前 reset 又中途 return，下一帧 vkWaitForFences 会永远等不到
        //   signal（死锁）。
        vkResetFences(device, 1, &inFlightFences_[currentFrame_]);
        vkResetCommandBuffer(commandBuffers_[currentFrame_], 0);
        recordCommandBuffer(commandBuffers_[currentFrame_], imageIndex, canvas);

        // ⑤ 提交：只在「写颜色」这个管线阶段前等 acquire（waitStages），
        //   之前的阶段（如顶点着色）可以提前跑，提高并行度。
        VkPipelineStageFlags waitStages[] = {VK_PIPELINE_STAGE_COLOR_ATTACHMENT_OUTPUT_BIT};
        vkQueueSubmit(graphicsQueue, 1, &submitInfo, inFlightFences_[currentFrame_]);

        // ⑥ present：等 renderFinished，顺序由 semaphore 在 GPU 上保证
        result = vkQueuePresentKHR(presentQueue, &presentInfo);
        if (result == VK_ERROR_OUT_OF_DATE_KHR || result == VK_SUBOPTIMAL_KHR) {
            swapchain_.requestRebuild(); continue;   // 本帧修正后再呈现
        }
        // ⑦ 轮转帧槽 0→1→0→1
        currentFrame_ = (currentFrame_ + 1) % gpu::kMaxFramesInFlight;
        return RenderResult::Rendered;
    }
    return RenderResult::Retry;   // 重试耗尽：放弃本帧不算失败，下帧再收敛
}
```

> **⚠️ 为什么一切错误都要「本帧内修正」**：持续渲染的引擎靠下一帧自然收敛错误；而这是**按需渲染**模型——画完一帧就没有「下一帧」了，错误画面会一直挂到下次事件。所以 OUT_OF_DATE / SUBOPTIMAL / 尺寸不匹配全都走「重建 → 同一份 canvas 重画」循环，最多 3 次（kMaxFrameAttempts），耗尽则返回 Retry 把请求留到下一 VSync。

> **⛔ 两个写死就会死的顺序**：① fence 必须**确认会提交之后才 reset**，否则中途 return 造成死锁；② 顶点上传必须在命令录制**之前**（命令引用的缓冲内容此时必须已就位）。

## 2.5 recordCommandBuffer：批次循环的五个动作

录制在 `recordBatchRange`（:622-738）里按批次推进，每个批次只有五个可能的动作：

| 动作 | 代码 | 什么时候发生 |
|---|---|---|
| 切管线 | vkCmdBindPipeline | 仅 SDF 批与普通批之间切换（主管线 ↔ SDF 管线），起始默认主管线 |
| 写 push constants | vkCmdPushConstants | range 开头写一次 mvp（112B 布局）；SDF 批追加前 96B（mvp + effectRect + effectParams） |
| 设 scissor | vkCmdSetScissor | 每批必做：batch.clip 与可视区求交 → 按旋转角换到 buffer 空间 → clamp 到目标尺寸 |
| 绑纹理 | vkCmdBindDescriptorSets | textureId 变化才重绑（0=白纹理，n=atlas 页/位图） |
| 画 | vkCmdDraw(vertexCount, 1, firstVertex, 0) | 每批一次；空批与 kBlur 标记批跳过 |

**性能细节**：mvp 在 range 开头只写一次，注释明确说「逐 batch 重复写会把录制成本放大，尤其是滚动时每帧都会重录整棵 UI」。clip 的旋转补偿（90°: (x,y)→(H−y−h, x) 等）与 NDC 补偿同向，保证剪刀矩形和顶点落在同一个空间。

**每个批次的 scissor 计算（vulkan_renderer.cpp:695-725）**

```cpp
// clip 与可视矩形求交（在视觉空间进行，与 app 布局坐标一致）
ui::Rect clip = ui::Rect::intersect(batch.clip, {0, 0, visualW, visualH});
// 需要补偿时，把视觉空间的 clip 旋转到 buffer 像素空间（与 NDC 补偿同向）：
ui::Rect bclip;
if (compensate && transform == VK_SURFACE_TRANSFORM_ROTATE_90_BIT_KHR)
    bclip = {visualH - clip.y - clip.h, clip.x, clip.h, clip.w};
else if (compensate && transform == VK_SURFACE_TRANSFORM_ROTATE_180_BIT_KHR)
    bclip = {visualW - clip.x - clip.w, visualH - clip.y - clip.h, clip.w, clip.h};
// 转 int32 时 clamp：offset 不小于 0，且 offset+extent 不超出渲染目标
int32_t ox = std::max(0, (int32_t)bclip.x);
int32_t ex = std::min((int32_t)(bclip.x + bclip.w), (int32_t)targetExtent.width) - ox;
if (ex <= 0 || ey <= 0) continue;   // 完全在屏外，跳过
VkRect2D scissor{{ox, oy}, {(uint32_t)ex, (uint32_t)ey}};
vkCmdSetScissor(cmd, 0, 1, &scissor);
```

## 2.6 离屏路径：背景模糊的四幕剧

`recordCommandBuffer` 在录制开头就分叉（:936）：无模糊帧**直通** swapchain（零离屏开销）；含 kBlur 标记帧整帧画进场景纹理。分叉条件：`!offscreenEffects_.ready() || !canvas.hasBlur()`。

1. **幕一 · 画场景** — beginScenePass(false) 清屏开画；遇到 kBlur 标记批就截断本段，之后的批次等模糊做完再画
2. **幕二 · 高斯 ping-pong** — recordBlurBackdrop：场景图转 SHADER_READ → H/V 两趟可分离高斯，全部在 1/4 降采样空间（σ 同步 ÷4，5 采样线性核按 σ≈3 标定，stepPing = σ/12）
3. **幕三 · 合成回场景** — 重开场景 pass（LOAD 保留内容），用 SDF mode=2 的 sdfBlit 管线把模糊结果按圆角遮罩合成回 blur 区域
4. **幕四 · 全屏 blit 上屏** — 场景图转可采样 → 主 pass 里一个全屏 quad 采样场景图画上 swapchain；旋转补偿集中在 blit 的 mvpDirect 里

**模糊区域出屏的快速返回（vulkan_renderer.cpp:752-756）**

```cpp
if (blurRect.w <= 0.0f || blurRect.h <= 0.0f) {
    // 区域出屏：不模糊不合成；场景 resolve 尚未被动过，调用方直接重开
    // 续画段即可。
    return false;
}
```

> **ℹ️ 跨帧屏障**：离屏三图（场景 resolve + ping-pong）是单实例，而渲染双帧在飞——上一帧的 blit 可能仍在 GPU 上采样它们。所以离屏帧首插一道全局内存屏障（以 `offscreenUsedOnce_` 记录是否需要），把本帧写入排在上一帧采样之后，否则滚动时会重影。

## 2.7 旋转补偿：一次矩阵乘法的事

呈现时系统把 buffer 按 currentTransform 旋转上屏，渲染器预先把 NDC 反向旋转（90/180/270 在 NDC 平面内是精确换轴），上屏后内容回到正立方向：

**mvpDirect 的构建（vulkan_renderer.cpp:884-911）**

```cpp
// 像素坐标 → NDC 的正交投影（原点在左上角，y 向下，基于视觉尺寸）。
// 注意 glm::ortho 第三/四参数是 bottom/top：Vulkan 正 viewport 高度下
// NDC +y 朝 framebuffer 下方，要 y 向下需传 bottom=0、top=height。
glm::mat4 mvpDirect = glm::ortho(0.0f, visualW, 0.0f, visualH, -1.0f, 1.0f);
if (surfaceTransform == VK_SURFACE_TRANSFORM_ROTATE_90_BIT_KHR)
    mvpDirect = rot90 * mvpDirect;    // (x, y) -> (-y, x)
// 180°: (x,y)->(-x,-y)；270°: (x,y)->(y,-x)
// 离屏场景按视觉方向绘制（不做补偿），纯正交投影；补偿集中在末段 blit。
```
