# 00 · 项目概览

estarx_vulkan 是一套小型跨平台 C++17 UI 框架，由 Vulkan 渲染，API 全面参照 Flutter 的保留式声明模型——但 **全部是 C++**：没有 view 句柄、没有 C 回调、没有 user_data 指针，也没有任何公开 C ABI 层。本指南按「语言特性 → 渲染 → 线程 → UI 框架 → 平台混合」的路线，带你逐层读透这个项目。

## 架构分层：从 App 到 GPU

整个 UI SDK 是 C++17 对象接口。C 链接只存在于 JNI、Objective-C 和平台工厂这类操作系统边界，不进入 App 或 UI 模块。自顶向下共六层：

1. **App** — StatefulWidget / State / build / Navigator::of(context) —— 应用代码只活在这一层
2. **Element tree** — mount / update / rebuild / unmount / BuildContext —— 常驻协调层
3. **View tree** — Flex / Button / ScrollView / Navigation —— 布局、绘制、命中测试
4. **Canvas** — 纯 CPU 顶点流 + Batch（按 clip × textureId 合批），帧契约
5. **Compositor** — buildFrame → 首帧日志 → Renderer::render —— UI 线程构帧，Raster 线程提交
6. **GPU 后端（core/src/gpu/）** — VulkanContext / Swapchain / UiPipeline / TextureCache / OffscreenEffects
7. **平台壳** — Android JNI · iOS Objective-C++ · 鸿蒙 NAPI —— surface / pointer / VSync / 生命周期

## 三棵树的分工

与 Flutter 的 Widget / Element / RenderObject 分工完全一致。理解这三棵树，就理解了这个框架的一半：

| 树 | 本质 | 生命周期 | App 能碰吗 |
|---|---|---|---|
| **Widget** | 不可变配置，build() 每次全新生成 | 用完即弃 | 能（唯一接触面） |
| **Element** | 常驻身份：新旧对比、持有 State 和 BuildContext | 跨重建存活 | 不能 |
| **View** | 保留渲染对象：实际尺寸、父子关系、滚动/按压态 | 跨重建存活 | 不能 |

> **💡 一条铁律**：唯一有资格裁决「复用还是重建」的角色是 **Element** —— Widget 和 View 都不能。App 不直接操作 View，因此不需要理解对象树的所有权规则。

## 平台边界：薄壳 + 共享内核

| 平台 | 薄壳 | 与另两端共享 |
|---|---|---|
| Android | JNI、ANativeWindow、MotionEvent、Choreographer | 全部 Widget / Element / View |
| iOS | Objective-C++、CAMetalLayer、CADisplayLink | 全部 Widget / Element / View |
| HarmonyOS | NAPI、XComponent（OHNativeWindow）、DisplaySync | 全部 Widget / Element / View |

> **ℹ️ HarmonyOS 为什么选 DisplaySync**：OH_NativeVSync 的帧回调运行在独立 vsync 线程，而 core 假设全部入口在同一线程。ArkTS DisplaySync 回调在 UI 线程，三端线程模型保持一致，core 无需引入锁。

## 构建与运行

**Android：**

```bash
./gradlew :samples:android:app:assembleDebug
# APK: samples/android/app/build/outputs/apk/debug/app-debug.apk
```

**HarmonyOS（DevEco Studio 5.0+）：**

```bash
export NODE_HOME="/Applications/DevEco-Studio.app/Contents/tools/node"
export DEVECO_SDK_HOME="/Applications/DevEco-Studio.app/Contents/sdk"
/Applications/DevEco-Studio.app/Contents/tools/hvigor/bin/hvigorw \
    assembleHap --mode module -p product=default --no-daemon
```

**契约测试（无需 Vulkan 设备）：**

```bash
sh tests/run_threading_test.sh     # 双槽背压 / Worker / 纹理快照
sh tests/run_ui_runtime_test.sh    # UI 运行时行为规格
sh tests/run_incremental_ui_test.sh
sh tools/check_log_format.sh
```

## 推荐阅读顺序

1. `samples/app/detail_page.cpp` —— StatelessWidget、组合布局、Navigator push
2. `samples/app/home_page.cpp` —— StatefulWidget、异步数据、事件订阅
3. `core/src/ui/widget_tree.h` → 头文件的类注释比实现更详细
4. `core/src/ui/widget_tree.cpp` → 从三棵树图（:26-33）读起
5. `core/src/ui/navigation/navigation_stack.cpp`
6. `tests/ui_runtime_test.cpp` —— 可执行的行为规格

目录按依赖顺序排列各主题：先把 C++ 语言底座看清楚，再进渲染与线程，最后落到 UI 框架与平台混合合成。
