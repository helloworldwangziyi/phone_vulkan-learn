# 06 · 滑动与手势：竞技场、ScrollView、拖拽

输入从平台 PointerEvent 到控件回调，中间隔着「每指状态机 + 命中测试 + 手势竞技场」三层仲裁；滚动、按压、拖拽这些交互态全部住在 View 层，不会因 Widget 重建而丢失。

## 6.1 输入链：从指针到控件

1. **平台 PointerEvent** — pointerId + 坐标 + 时刻
2. **per-pointerId 状态表** — pointer_input.cpp：每根手指一条独立状态机
3. **View hit test** — 每指独立选定 target / panTarget / scaleTarget
4. **手势竞技场仲裁** — tap / double tap / long press / pan / scale 先到先赢
5. **派发** — Button、ScrollView、GestureDetector 或 Navigation

> **ℹ️ 竞技场规则与真实常量（pointer_input.cpp，1051 行）**：同一序列**先到先赢，输家收 Cancel**：pan（位移超触控阈值）与 scale（同视图集齐双指）胜 tap 系；long press（500ms 截止，计时复用动画调度器的每帧 tick）触发只废 tap 系，之后仍可认领 pan；设了 onDoubleTap 的目标单击挂起 300ms 等待第二击。同一视图同一时间只允许一根手指的 pan 生效（排他）。选定接收者后锁定到 End 或 Cancel，不会因接收者中途进入动画状态而重新竞争。写死的常量：touch slop 12px、长按 500ms、双击 300ms/48px。

## 6.2 ScrollView / ListView：滚动如何工作

- **布局**：视口 biggest() 撑满父约束；内容在滚动方向拿 kInfinite 测自然高度——这正是「滚动方向无界」语义的用途；
- **位移 ≠ 布局**：滚动 offset 存在 View 层，逐帧滚动只写偏移（setPosition），不触发布局；markNeedsLayout 标脏冒泡到根后从根重排（flushLayout）；
- **实现位置**：core/src/ui/view/scroll_control.cpp —— 拖动、惯性、橡皮筋与回弹的完整状态机；
- **列表身份**：数据驱动、顺序会变的列表用 `keyed(Key(业务主键), ...)` 保住行状态；行情行带完整 operator==，可见字段没变就不重建这一行。

### 真实的物理参数（scroll_control.cpp:24-32）

真实实现用的是**物理公式驱动**而不是逐帧衰减系数——每帧按流逝时间算位置，丢帧只少画中间点，动画时长不漂移：

**fling 运动学（scroll_control.cpp:392-405）**

```cpp
constexpr float kRubberBand = 0.45f;          // 橡皮筋阻尼
constexpr float kFlingMinVelocity = 50.0f;    // px/s：低于它不启动惯性
constexpr float kFlingStopVelocity = 30.0f;   // px/s：低于它停住
constexpr float kFlingDeceleration = 2400.0f; // px/s²：摩擦减速度
constexpr int64_t kSpringDurationNanos = 250'000'000;  // 回弹 250ms

// t 秒时的瞬时速度（线性减速到 0 停住）
float flingVelocity(float v0, float t) {
    return std::copysign(
        std::max(0.0f, std::fabs(v0) - kFlingDeceleration * t), v0);
}
// t 秒时的位置：匀减速位移公式 s = v0·t - ½·a·t²
float flingPosition(float from, float v0, float t) {
    const float elapsed = std::min(t, std::fabs(v0) / kFlingDeceleration);
    return from + std::copysign(
        std::fabs(v0) * elapsed - 0.5f * kFlingDeceleration * elapsed * elapsed, v0);
}
// 每帧: view->rawX = flingPosition(fromX, velocityX, t);
//       当 |v| < 30 且越过边界时 → 启动 250ms 弹簧回弹
```

## 6.3 拖拽与投放：Draggable / DragTarget

与 Flutter 的 Draggable&lt;T&gt; 职责拆分一致：控件本身不重排模型，交换、插入哪些数据由业务决定。

| 组件 / 配置 | 职责 |
|---|---|
| `DragDropRegion` | 管理会话、目标命中、目标亮框和最上层反馈；每个区域同时拖一个对象 |
| `DraggableOptions::data` | 发起时复制的 std::any 数据，可 any_cast 检查类型 |
| feedback / placeholder | 在源控件尺寸内绘制跟手副本 / 原位占位；原控件保留布局空间 |
| `DragTargetOptions::canAccept` | 纯判断函数，决定类型、区域等条件是否允许投放 |
| `onAccept` | 松手成功投放时更新业务数据，例如交换两个元素并 setState |
| `onDragEnd` | 成功或取消后通知拖拽源；取消不提交交换 |

**一个格子同时作为拖拽源和投放目标**

```cpp
return dragDropRegion(scrollView(buildContent()));  // 区域在视口外层

DraggableOptions source;
source.data = itemId;
source.feedback = [itemId](PaintContext& paint) {
    drawItem(paint, itemId);   // 应用提供的绘制函数
};

DragTargetOptions target;
target.canAccept = [itemId](const std::any& data) {
    const auto* dragged = std::any_cast<int>(&data);
    return dragged && *dragged != itemId;
};
target.onAccept = [this, itemId](const std::any& data) {
    const int dragged = std::any_cast<int>(data);
    setState([this, dragged, itemId] {
        swapItems(dragged, itemId);  // 应用按稳定 ID 交换模型中的位置
    });
};

return dragTarget(draggable(buildItem(itemId), std::move(source)),
                  std::move(target));
```

> **💡 实现要点**：拖动超过现有 pan 阈值后才启动，不会把轻微触摸识别为拖拽。移动只更新保留的 View，不逐帧重建页面。源被删除、禁用、换掉子视图、隐藏、页面离开、窗口尺寸改变或收到 Cancel 时取消会话。跨父节点的交换由业务交换模型实现——需要保留的业务状态按稳定 ID 存储。

> **⚠️ 当前边界**：立即拖拽，反馈由 painter 绘制；长按启动、任意 Widget 反馈、自动边缘滚动、插入排序动画仍待扩展。带拖拽能力的块优先消费 pan，页面滚动可以从空白处开始。反馈位于当前 Vulkan 页面内，不覆盖原生 WebView。
