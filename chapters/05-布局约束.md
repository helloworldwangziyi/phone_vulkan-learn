# 05 · 布局：盒约束协议

布局系统只有一条协议（Flutter 的盒约束模型）：**约束下行，尺寸上行，位置父定**。整个框架不知道「设计稿」的存在，App 在 build 时把设计稿像素换算成真实像素烘焙进 Widget，协议流动的全是真实像素。

## 5.1 BoxConstraints 词汇表

| 术语 | 含义 | 例子 |
|---|---|---|
| **tight** | min == max，强制尺寸 | tight(400, 140) = 必须恰好 400×140 |
| **loose** | min = 0，只有上限 | 「随意，但别超过 max」 |
| **无界** | max = kInfinite | 滚动方向、Column 主轴 |
| **deflate** | 四边 min/max 同步内缩（Padding 用） | render_view.cpp:68 |
| **biggest()** | 有界取 max（撑满），无界取 min（0） | 裸 View 默认行为 |

View::layout() 入口把孩子回报的尺寸 constrain() 钳进 [min, max] 再写入——父给的 tight 不可违抗，子类 performLayout 报出超限尺寸也会被钳回去。rect 语义拆分：**w/h 由自身 layout 写，x/y 由父 setPosition 写**。View 布局时不知道自己在屏幕哪里，只知道自己的尺寸。

## 5.2 layout 是模板方法：骨架固定，钩子开放

View::layout()（render_view.cpp:256）固定做五件事：

1. **幂等短路**：约束未变且子树无脏 → 直接返回缓存尺寸，不递归（整树 flush 经过干净子树开销为零，性能关键）；
2. 存下约束（供 flushLayout 重排复用）；
3. 虚调用 performLayout——dispatch 到实际控件类型；
4. constrain 钳制后写 rect.w/h，尺寸变了才 markNeedsPaint；
5. 清脏标记，requestRender。

子类只需回答一个问题：**给我这个约束，我想多大**。框架不变量（钳制、写尺寸、缓存、清脏）收在基类，子类无法破坏——与 updateChild 的「唯一对比规则」同一设计哲学。控件集合开放且树内异构混合，所以用运行期虚函数而非编译期多态。

## 5.3 各控件如何回答协议

| 控件 | 实现 | 策略 |
|---|---|---|
| `SizedBoxView` | basic.cpp:24 | 显式轴锁 tight；未锁轴有界撑满、无界包孩子 |
| `PaddingView` | basic.cpp:56 | 约束 deflate 下行，回报 = 孩子 + 边距 |
| `CenterView` | basic.cpp:80 | **把 tight 松掉**（min 清零）让孩子自测，自身撑满后居中 |
| `StackView` | basic.cpp:103 | 全部孩子松约束自测、左上落位，无界包最大孩子 |
| `FlexView` | flex_layout.cpp:40 | 两段式：先无界主轴测非弹性孩子，再把剩余主轴空间按 flex tight 分给 Expanded |
| `ScrollView` | scroll_control.cpp:233 | 视口 biggest() 撑满；内容在滚动方向拿 kInfinite 测自然高度 |
| `TextView` | text.cpp:27 | 叶子：量文字实际宽高后钳制回报 |

> **ℹ️ Center 的设计动机**：tight 在 View 层松掉，居中意图不再经 flexParentData 上传——那条路在非 Flex 父级下会断（tight min 会把孩子钳大）。

边界规则：主轴无界时遇弹性孩子（Expanded）收敛为 0（Flutter 在此直接报错）；无界轴上裸 View 尺寸为 0（biggest 取 min），所以 Column 的孩子要么有内容、要么显式尺寸。

## 5.4 Widget → View 的创建时机

createRenderObject 在 RenderObjectElement::firstMount() 里调用，**该位置 Element 上岗时恰好一次**；之后同类型重建走 updateElement → updateRenderObject 把新参数刷到已有 View，View 不重建。约定：createRenderObject 内部直接调 updateRenderObject 刷首份参数，参数应用逻辑只写一份。

> **💡 View 的创建与布局是两个时期**：createRenderObject 在 mount 期，尺寸要等布局期。挂树时 rect 还是 0×0。

## 5.5 完整推演：panel 的一次布局

设备 A（1080×2400，scaleRatio = 1.0），panel 的约束流（宽 tight，主轴无界的 Column 下行）：

```text
Column 下行 {minW:1080, maxW:1080, minH:0, maxH:∞}
  → Padding  deflate(200, 60) → {880, 880, 0, ∞} 给孩子
    → SizedBox  宽未锁有界撑满 880，高锁 540
      → Container  biggest() → 880×540
  ← Padding 回报 880+200 × 540+60 = 1080×600，钳制恰满足 tight
  ← setPosition(100, 60)  内容区起点
```

设备 B（1440×3120，scaleRatio ≈ 1.3333）：全部数值 ×1.3333，内容等比放大，App 代码不变。resize 链路：SurfaceChanged → 更新比例 + setViewportSize 改根约束 → 级联重排；烘焙在 Widget 里的固定尺寸要等下一次 rebuild 才按新比例重算。

## 5.6 写页面时的五条实战规则

1. 无界轴上裸 View 尺寸为 0——Column 的孩子要有内容或显式尺寸；
2. tight 不可违抗——父给 tight，孩子报多大都会被钳回去；
3. 想让孩子按内容定尺寸，中间垫 Center（它松掉 tight）；
4. 滚动区域里 Expanded 分到 0（主轴无界）；
5. painter 回调里是视图局部坐标——用 (0,0) 到 paint.size() 画画，位置不归你管。

**自定义布局控件的套路**（对照 PaddingView）：拿到约束 → 决定给孩子什么约束 → 收孩子尺寸 → setPosition 摆孩子 → 报自己尺寸。
