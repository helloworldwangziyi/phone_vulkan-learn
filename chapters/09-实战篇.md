# 09 · 实战：从行情数据到首页布局

前八章讲的是机制，本章讲实施：拿项目里真实的行情功能和首页代码，走一遍「服务器上一笔行情 → 屏幕上红绿数字跳动」的完整链路，再推演首页布局为什么这样写。每一段讲解都对着真实源码。

## 9.1 行情接收全链路

### 第一站：配置——21 个端点，批量竞速

行情客户端的配置在 `samples/estarx/market/market_config.cpp:4-39`：`appMarketConfig()` 返回一个 `CspConfig`，里面最显眼的是 21 个行情端点（北京云、成都云、广州云、香港云、上海云……外加一个 IPv6）。这不是冗余，而是**多线路竞速**的弹药库，注释写明了出处：对照易星 SDK 的 `0001.lua QUOTE_ADDR_INFO`。

```cpp
// samples/estarx/market/market_config.cpp（节选；端点表与授权串略去）
config.endpoints = {
    // 21 个行情端点（IP + 端口 + 线路名），对照 SDK 0001.lua QUOTE_ADDR_INFO。
    // 注意：这类端点表随客户端 SDK 分发，属于半公开信息，不建议原样公开。
};
config.license = /* 授权标识串（客户端标识，连接时上行），略去 */;
config.mainExchanges = {"ZCE", "DCE", "SHFE", "INE", "GFEX", "CFFEX"};
config.maxSubscriptions = 256;
```

两个细节：端点一律填**数字 IP 而不是域名**（`csp_client.h:17` 注释：保持连接超时不被 DNS 拖累）；`module` 在 Apple 平台填 `'I'`、其余填 `'A'`，模拟 SDK 的平台标识。`mainExchanges` 列出六大期货交易所，客户端会拉取各所的主力合约映射并订阅有权限的真实合约。

### 第二站：CspClient——一条通信线程，poll 事件循环

`core/src/net/csp/csp_client.h:83-84` 的类注释是整个设计的纲领：

> One owned communication thread. Snapshots are immutable and safe to retain on UI. Poll revision() once per UI frame and read snapshot() only when it changes.

**连接竞速**（`csp_client.cpp:116-161`）：`connect()` 不逐个试，而是每批起 4 个非阻塞 `connect`，`poll` 等到候选集合里**第一个可写的 socket** 胜出，`next` 记录轮转位置保证下次从备用线路开始。任何一个端点连不上都不致命，21 个全失败才抛出「无法连接行情服务器」。

**协议状态机**：`CspPhase`（`csp_client.h:41-45`）定义了 12 个阶段，`Connecting → Authenticating → LoggingIn → LoadingContracts → …… → Ready`，每个阶段的变化都会进快照——这就是首页副标题「正在连接行情服务器」文字的来源。

**发布合帧**（`csp_client.cpp:203-217`）——本章最重要的一个 if：

```cpp
if (session.dirty && (session.state.phase != previousPhase || now - lastPublished >= Milliseconds(16))) {
    auto visible = session.state;
    if (!visible.ready()) {
        // 断线/重连中：旧报价保留，统一标 stale——「上次数据」而不是空白
        const auto previous = stateCopy();
        if (visible.quotes.empty()) visible.quotes = previous.quotes;
        else for (auto& quote : visible.quotes) if (!quote.received) { /* 用旧值补齐 */ }
        for (auto& quote : visible.quotes) quote.stale = true;
    }
    publish(std::move(visible)); session.dirty = false;
    lastPublished = now; previousPhase = session.state.phase;
}
```

行情是高频数据，不能每来一笔就发布一次（那会把 UI 线程淹掉）。规则：**距上次发布满 16ms 才发，但阶段变化立即发**。且发布时构造的是全新 `CspMarketState` 副本——快照不可变，UI 拿着旧指针随便读，这就是 `shared_ptr<const CspMarketState>` 的含义（`csp_client.cpp:108-113`：锁内 `revision + 1`、换指针，两步完成，无锁读侧）。

**超时与背压**：心跳超时（`csp_client.cpp:195`）判连接已死抛异常进入重连；未 Ready 超过 60s 判初始化失败；发送队列超 1MB 直接掐断。重连退避是指数式：`reconnectDelayMs × 2^n` 封顶 30 秒（`csp_client.cpp:302`），`retry()` 可立即打断退避。

### 第三站：应用桥接——每帧一次 revision 轮询

通信线程只管 socket，它不知道怎么通知 UI（EventBus 只在 UI 线程操作）。桥接在 `samples/estarx/market/market_data.cpp:17-37`：

```cpp
void startMarketData() {
    if (client) return;
    client = std::make_shared<evk::CspClient>(appMarketConfig());
    // ……
    client->start();
    evk::ui::startAnimation([source = client, cancel = canceled, revision = uint64_t{0}, ...](int64_t) mutable {
        if (*cancel) return true;
        if (source->revision() == revision) return false;   // 没变，下帧再看
        current = source->snapshot(); revision = current->revision;
        // VSync polls the latest immutable state once. No per-tick UI queue grows.
        evk::ui::EventBus::instance().emit(kEventMarketData);
        return false;   // 常驻，不自我了断
    });
}
```

一个常驻动画回调挂在 VSync 上，每帧做两件事：比对 `revision`，变了才取快照、广播事件。效果等价于 Flutter setState 的合并语义——**一帧内无论来多少笔行情，UI 最多重建一次**。没有条件变量、没有消息队列，就是一个数和一个指针。

这个 `startAnimation` 动画回调的生命周期有个坑：`AppResumed` 可能早于 `EngineReady`（华为等机型实测），此时 UI 未挂载，`runApp→shutdownApp` 会把动画清掉，而 `if (client) return` 又阻止重挂。所以 `app_entry.cpp:151-157` 里 resume 路径加了 `if (evk::ui::appNavigator())` 守卫，真正的挂载点在 `createUi()` 末尾（`app_entry.cpp:118`）。

### 第四站：前后台——连接不断，只降频率

成熟行情 App 退后台不能断连接（重连代价大、会丢数据）。`app_entry.cpp:146-157` 把生命周期事件翻译成行情指令：

| 生命周期事件 | 调用 | 行为 |
|---|---|---|
| `AppPaused` | `pauseMarketData()` | `setBackground(true)`：poll 空闲间隔 25ms → 500ms，心跳节奏不变，服务器会话不掉（`csp_client.cpp:221`） |
| `AppResumed` | `resumeMarketData()` | 恢复前台节奏；若连接已死（iOS 挂起冻死的 socket）打断退避立即重连；Ready 则不动——零重连 |
| `AppTerminating` | `stopMarketData()` | 停止线程，最终快照 phase = Stopped |

### 第五站：页面消费——三层各管一段

事件 `kEventMarketData` 发出后，首页有三个订阅者，各自只重建自己（`home_page.cpp`）：

**① 状态副标题**（`home_page.cpp:205-225`）：`HomeMarketStatusState` 的 `didMount` 里 `listen`，收到事件调 `refresh()`，文案变了才 `setState()`：

```cpp
void refresh() {
    auto next = marketStatusText(*appMarketState());
    if (next == status_) return;    // ← 判等：「行情已连接 · 北京云」没变就不重建
    status_ = std::move(next);
    setState();
}
```

`marketStatusText()`（`market_data.cpp:119-124`）是纯函数：Ready 显示「行情已连接 · 端点名」，Failed 显示「行情服务暂不可用（错误码），点击重试」，Reconnecting 显示「正在重连 · 显示上次数据」。连接状态机的每一次跳转都直接映射为一行 UI 文案。

**② 行情行**（`home_page.cpp:247-263`）：`HomeQuoteModel::update()` 把 `CspQuote` 派生成展示串（名称+代码、价格+涨跌、stale、方向），与旧值做 `operator==` 比较——**可见字段没变，什么都不发生**；变了才通过 `changed` 回调通知持有它的行 State：

```cpp
void update(const evk::CspQuote& quote) {
    const auto change = marketChange(quote);
    HomeQuote next{ /* 标题、价格串、stale、涨跌方向 */ };
    if (value == next) return;          // ← 一行一模型，报价刷新不打脏其他行
    value = std::move(next);
    if (changed) changed();
}
```

价格格式化也是纯函数：`marketPrice()`（`market_data.cpp:96-104`）用 `%.8f` 打印后剥尾零，`marketChange()`（:105-111）取最新价减昨结价、参考价为 0 时回退今开。

**③ 行情列表**（`home_page.cpp:310-354`）：`HomeMarketListState::refresh()` 返回 `bool`——合约**增删/换序**才返回 true 触发 `setState()` 重建列表结构；普通报价更新在行级已被 `model->update()` 消化。行身份靠 `keyed(Key(contract))` 保住，「业务主键 = 列表 key」让刷新后每行的 State（含绑定的 changed 回调）原地保留。

### 完整数据流

```text
行情服务器
  │ socket 字节流
  ▼
CspClient 通信线程（csp_client.cpp）
  recv → 协议解码 → session.state 变脏
  │ 16ms 合帧（phase 变化立即发）
  ▼
publish()：revision + 1，shared_ptr 原子换指针（csp_client.cpp:108-113）
  │
  ▼
UI 线程：startAnimation 常驻回调每帧比对 revision（market_data.cpp:24-36）
  │ 变了：取快照 → EventBus::emit(kEventMarketData)
  ▼
页面 listen 回调（UI 线程串行）
  ├─ HomeMarketStatus.refresh()：文案判等 → 自身 setState
  ├─ HomeMarketList.refresh()：结构判等 → 自身 setState（行级变化已被 model 消化）
  │   └─ HomeQuoteModel.update()：字段判等 → changed() → HomeQuoteRow.setState
  ▼
帧头脏队列合帧（depth 排序，100 次 setState 合并成 1 次 build）
  ▼
buildFrame → FramePipeline → Raster 线程渲染上屏
```

全程零锁读行情：UI 侧只有「读原子 revision」和「拷贝 shared_ptr」两个操作，通信线程随便写新快照，旧快照照样有效。

## 9.2 首页布局：从设计稿到约束流

### 设计稿基准：所有数字都不是像素

首页里没有一个写死的像素值，全部经 `appCalcWidth/appCalcHeight` 换算（`samples/estarx/screen_metrics.h:3-13`）：

> 约定设计稿 1080×2339，所有布局尺寸写 appCalcWidth/Height(设计值)，运行期按屏幕等比缩放。scaleRatio = min(屏宽/1080, 屏高/2339)。

实现上 `appCalc` 委托给 core 的 `evk::ui::dp`（`screen_metrics.cpp:47-53`），比例引擎在 `core/src/ui/design_metrics.h`。比例由 `SurfaceChanged` 驱动更新（`app_entry.cpp:123-128`），之后 Flex 级联重排，**页面代码不响应 resize**。

### 页面组织范式：build 就是装配单

`home_page.cpp:30-32` 的注释定了调子：build() 只做区块直排装配，**参数顺序 = 屏幕自上而下顺序**，每个区块一个 `buildXxx()`。看 `build()`（`home_page.cpp:376-400`）：

```cpp
auto page = column(
    buildHeroPanel(theme),          // 首屏装饰面板
    buildDetailEntry(theme),        // 详情页演示
    // ……九个 demo 入口……
    buildShapeStrip(),              // 图元演示条
    buildMarketHeader(theme),       // 「行情速览」标题 + 状态副标题
    buildMarketList());             // 行情列表
static_cast<Column*>(page.get())->color = theme.windowBackground;
return scrollView(std::move(page)); // 整页可滚，Column 高度自动测量
```

页面级状态只有三项（`home_page.cpp:627-629`）：面板强调色开关、详情页计数、平台信息串。**所有会随行情/主题/路由变化的状态都沉到了独立 StatefulWidget 里**，页面本身几乎不可变。

### 行情区块的约束流推演

以 1080×2400、scaleRatio = 1.0 的设备为例，从 `buildMarketHeader`（`home_page.cpp:572-584`）和 `buildMarketList`（:588-599）逐层往下推：

```text
scrollView
  └─ Column（主轴无界：整页内容高度由内容决定，可滚动）
      ├─ buildMarketHeader → Column（同样无界主轴）
      │    ├─ padding(左右 100) → text「行情速览」56 号粗体
      │    │     设计宽 1080 − 200 = 880，文字量宽后钳制回报
      │    └─ padding(左右 100, 上 8) → HomeMarketStatus
      └─ buildMarketList → padding(左右 100, 上 40, 下 24)
           └─ sizedBox(-1, 600) → HomeMarketList
                -1 = 宽轴不锁：有界撑满 880
                600 = 列表视口高，写死的设计稿值
```

对照第 05 章的协议：**约束下行，尺寸上行，位置父定**。`sizedBox(-1.0f, appCalcHeight(600.0f), …)` 的 `-1` 是「这一轴交回给约束」的惯例写法。行情列表为什么拿固定 600 高视口而不是 Expanded？注释直接给了答案（`home_page.cpp:586-587`）：

> 整页滚动时没有可分配的剩余高度，给独立列表明确的视口高度（600）。

整页是 ScrollView，Column 主轴无界——无界主轴上 Expanded 分到 0。这是第 05 章「滚动区域里 Expanded 分到 0」规则的直接应用。

行内布局（`home_page.cpp:288-292`）：

```cpp
return padding(
    EdgeInsets::symmetric(appCalcWidth(16), appCalcHeight(12)),
    column(
        text(quote.title, appCalcHeight(29), theme.textPrimary, appFonts::cjk()),
        text(quote.price, appCalcHeight(28), color, appFonts::cjk())));
```

行 = 左右 16 内边距 + 两行文字（29 号标题 / 28 号价格），涨红跌绿（`0xEF5350FF` / `0x26A69AFF`）、stale 灰化。这一行在 Column 里高度由文字量决定，列表整体在 600 高视口内滚动。

### 一个容易忽略的细节：字号的两种换算时机

首页里字号有两种写法，时机不同：

- **build 时换算**：`text(quote.title, appCalcHeight(29), …)` —— 尺寸烘进 Widget 树， rebuild 时才更新（resize 后要等下一次 rebuild）。
- **绘制时换算**：`centeredTextPainter(label, 36.0f, …)`（`home_page.cpp:52-67`）—— painter 里存设计值，`paint` 时才 `appCalcHeight(fontHeight)`，注释明说「屏幕尺寸变化无需重建即随动」。

自绘区域用第二种，系统控件用第一种，各取所需。

## 9.3 产品级首页：同一套机制，更多区块

demo 首页是教学切片；真正的产品首页在 `samples/estarx/home/`，结构完全一样、区块更多：`portal_home_page.cpp`（装配 + 五个 tab）+ 九个独立区块文件（`top_bar` / `banner_area` / `grid_area` / `watch_section` / `hot_section` / `trend_section` / `rank_section` / `notice_area`）。以盯盘区为例（`watch_section.cpp:13-25`）：

```cpp
std::unique_ptr<evk::ui::Widget> quoteCell(const AppTheme& theme, ...) {
    const uint32_t color = up ? theme.upColor : theme.downColor;
    return expanded(column(widgetList(
        center(text(name, fontPx(13.0f), theme.textPrimary, appFonts::cjk())),
        padding(EdgeInsets::only(0.0f, py(4.0f), 0.0f, 0.0f),
            center(text(price, fontPx(19.0f), color, appFonts::cjkBold()))),
        // 涨跌串……
    )));
}
```

一行三个 `expanded` 单元均分宽度（Flex 剩余空间按 flex 分配，见第 05 章），展开态一页两行六个，配 `PageView` 轮播 + 指示点。当前盯盘区还是占位数据（`watch_section.cpp:27-41` 注释：行情接入前的静态展示），接入时只需把 `kWatchQuotes` 换成 `appMarketState()` 快照的派生值——链路在 9.1 节已经全程打通，模型层的 `HomeQuoteModel` 判等、行级回调、keyed 保身份，原样复用。

> **💡 本章的方法论**：实施一个新功能时，项目给出的路径是——通信与并发收进 core 的一条线程（`CspClient`），应用层只做纯函数格式化和一把快照指针（`market_data.cpp`），UI 层用「状态下沉 + 判等 + 一帧合并」消化高频更新（`home_page.cpp`），布局层用「设计稿换算 + 区块直排 + 明确视口高度」落地（`screen_metrics.h` + `buildXxx`）。四层的每一段都能单独测试、单独读。
